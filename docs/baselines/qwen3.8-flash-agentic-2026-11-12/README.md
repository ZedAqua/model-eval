# Qwen3.8-Flash Agentic 基线与 DS + Hermes 对照（2026-11-12）

Agentic 侧评测用 **Qwen3.8-Flash** 代替 Qwen3.8-27B：模型侧评测（见 [`qwen3.8-27b-2026-11-19`](../qwen3.8-27b-2026-11-19/README.md)）在本地 vLLM 上测 27B，Agentic 评测需要接入公司 Hermes 端到端运行，这一轮用已有的 Qwen3.8-Flash 结果。**Qwen3.8-Flash 与 Qwen3.8-27B 不是同一个模型**，这里的分数不能当作 27B 的 Agentic 基线。

所有分数只做内部比较，不作为官方榜单成绩。逐题输出、对话轨迹和判分明细不进 Git。

## 运行条件

| 项目 | 取值 |
|---|---|
| Agent 框架 | 公司 Hermes（内部版本，两侧固定为同一提交）与基线 Profile |
| 对照方式 | 只换主模型；Hermes 提交、工具、题目、裁判与 DS 基线相同 |
| Qwen 侧模型 | Qwen3.8-Flash，推理强度 max（SpreadsheetBench 2 为 xhigh） |
| DS 侧模型 | `deepseek-v4.1-flash-1017` |
| 裁判 | gpt-6.1-sol，各基准官方判分模板；τ²-bench 用户模拟器 gpt-6.1-sol（low） |
| 分母 | 完整题数；超时、断连、内容拦截、判分错误分别记录，不删除失败题 |
| 运行次数 | 每题一次 |

### 差距归因要点

逐题审计结论（只把能确认是模型原因的失败当作训练目标）：

- **τ²-bench telecom**：Qwen 输、DS 赢的 11 题里，9 题是常规排查无效后没有提出新假设（例如向用户确认是否在境外、启用漫游）就转人工；1 题第一次操作后未确认问题解决就结束；1 题口头说转接但没有调用转接工具。airline、retail 的双向翻转基本持平，属于单次运行噪声。
- **Seal-0**：先有环境混杂再有模型问题。Qwen 批次的公司搜索工具约 27% 调用返回第三方搜索额度错误（DS 批次约 1.5%），另有 8 题最终回复残留 `</think>` 标签、2 题请求直接报错。在此之上，可见的模型问题包括：已找到反证仍不更新答案、为迁就候选答案改写题目条件、结构化数据（表格续行）解析与总量对账不足。
- 搜索类差距不能完全归因到模型：DS 批次运行时搜索服务额度充足，Qwen 批次没有；两侧运行时间和链路不同。

## 各评测测什么

| 评测 | 能力 | 判分 | 属性 |
|---|---|---|---|
| FinSearchComp T2/T3 | 从权威来源查金融数字与事实（T2 历史查询，T3 复杂调研） | LLM 按官方模板判对错 | 提升项 |
| xbench-DeepSearch | 跨多个网页串联线索的多步深度搜索 | LLM 判分 | 提升项 |
| BrowseComp | 需要大量检索、反复试错的网页浏览 | LLM 判 yes/no | 提升项 |
| Seal-0 | 搜索结果矛盾或有噪声时仍给出正确答案 | SimpleQA 模板 | 提升项 |
| τ²-bench | 多轮业务对话中按政策调用工具、改对系统状态 | 对比数据库最终状态 | 提升项 |
| Finance Agent | 读财报公告、检索计算、给出有据结论 | 按要点评分 | 保护项 |
| SpreadsheetBench 2 | 表格调错、金融建模、按模板填表 | 官方验证器检查输出文件 | 保护项 |
| SWE-bench Verified | 真实开源仓库修 bug | 官方测试 | 保护项 |

提升项看训练后是否上升，保护项看是否下降。
